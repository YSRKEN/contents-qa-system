# LLMの設定

このシステムは**LLMが無くても動きます**。取得・抽出・登録・検索はすべて手元で完結し、
外に出るのは取得先のサイトだけです。LLMを使うのは次の3か所だけで、いずれも代わりの手順があります。

| 使う場所 | LLMが無い場合 |
|---|---|
| `cqs ask` の回答生成 | 材料と**そのまま貼れるプロンプト**を出力します。お使いのAIチャットに貼れば同じ答えになります |
| 質問の計画・次に訊けること | 飛ばして、従来どおりの一発検索になります |
| `images transcribe`（画像の読み取り） | `cqs images save` で画像を保存し、読んだ結果を `cqs add-text --kind image_transcript` で入れます |
| `cqs restate`（原文から主張を起こす） | `--prompt` でプロンプトを出し、AIチャットが返したJSONを `--apply` で取り込みます |

**貼って使うのが正式な使い方のひとつです。** キーが無い環境でも機能が削られるわけではなく、
回答を書く相手が自分の使っているチャットに変わるだけです。出典・確認状態・区分の扱い方は
プロンプトに全部入っているので、貼られた側は同じ制約で答えます。

**キーを登録すると、この貼り付けが自動になります。** 下の設定を入れた時点で、
`cqs ask` は回答まで書き、`cqs restate` は原文を読んで踏み込んだ主張を自分で起こして
登録します。貼って使う道もそのまま残るので、どちらを使ってもDBに入るものは同じです。

```
$ cqs -w 作品名 ask "ほむらとまどかの関係は？"
# 使った検索語: 暁美, 鹿目, 関係
# 知識層の主張
- [claim 2645] 第1話: まどかの通うクラスにやってきた、一人の転校生・暁美ほむら。
    確認状態: 公式確認（official） / 出典種別: 公式サイト / 区分: TVシリーズ / 出典: https://…
…
LLMの設定が無いため、回答生成は行いませんでした。上のプロンプトを、お使いのAIチャットに
そのまま貼れば同じ答えが得られます。
```

## 自動で答えさせる

提供元は問いません。**OpenAI互換のAPI**（OpenAI本体、LM Studio、Ollama、vLLM、
各種ホスティング）と **AnthropicのMessages API** のどちらでも動きます。
どちらも標準ライブラリのHTTPで叩くので、**追加のパッケージは要りません**。

```bash
# OpenAI
export OPENAI_API_KEY=sk-...
export CQS_MODEL=gpt-4o-mini

# OpenAI互換のローカルサーバ（LM Studio など）。キーは不要なことが多い
export CQS_LLM_BASE_URL=http://localhost:1234/v1
export CQS_MODEL=<そのサーバでのモデル名>

# Ollama
export CQS_LLM_BASE_URL=http://localhost:11434/v1
export CQS_MODEL=qwen3:8b

# Anthropic
export ANTHROPIC_API_KEY=sk-ant-...
export CQS_MODEL=claude-opus-5
```

### 環境変数

| 変数 | 既定 | 用途 |
|---|---|---|
| `CQS_LLM_PROVIDER` | 自動判定 | `openai` / `anthropic` / `none`。`none` で明示的に切る |
| `CQS_LLM_BASE_URL` | 提供元の既定 | APIの基点。`OPENAI_BASE_URL` / `OPENAI_API_BASE` でも可 |
| `CQS_LLM_API_KEY` | — | APIキー。`OPENAI_API_KEY` / `ANTHROPIC_API_KEY` でも可 |
| `CQS_MODEL` | `gpt-4o-mini` / `claude-opus-5` | モデル名。`OPENAI_MODEL` でも可 |
| `CQS_LLM_TIMEOUT` | `180` | 1回の問い合わせの上限秒数 |

自動判定は「`CQS_LLM_BASE_URL` か `OPENAI_API_KEY` があれば OpenAI互換、
`ANTHROPIC_API_KEY` があれば Anthropic、どちらも無ければ未設定」です。
ローカルのサーバはキーを要らないことが多いので、基点だけでも動きます。

現在の設定は `python -c "import cqs.llm as l; print(l.describe())"` で確認できます。

## 画像の読み取りについて

`images transcribe` は画像をそのままモデルへ送ります。画像を受け取れないモデルでは
失敗するので、その場合は `images save` で保存し、手元のチャットに読ませてください。

## 原文から主張を起こす（restate）

機械的な文分割は説明文には効くが、物語には効かない。地の文とセリフは主語を
繰り返さないので、文だけを取り出すと断片になる。

    「アイドルとしての才能は欠片もない。」     ← 誰が誰に言ったのか分からない
    「その努力は、無駄だというのに。」

こうなると、検索語も当たらず、読んでも意味が取れない。`cqs restate` は原文の
一区切りをLLMに渡し、**それだけを読んで意味が通る主張**に言い直させる。

    白草四音は葛城リーリヤに「アイドルとしての才能は欠片もない。」と告げ、
    矛先をプロデューサーへ向けて「あなたはなぜこれを選んだのですか？」と、
    リーリヤを選んだこと自体を侮辱した（第17話）。

### キーを登録しているとき

呼び出しから登録まで通しで走る。

```bash
cqs -w <作品> restate <版ID>                 # 何ができるか見る（登録しない）
cqs -w <作品> restate <版ID> --register      # 知識層に入れる
cqs -w <作品> restate <版ID> --max-chunks 2  # 少しだけ試す
```

### キーが無いとき

`--prompt` で同じプロンプトを出し、手元のAIチャット（Claude Code、ChatGPTなど）に貼って、
返ってきたJSON配列をファイルに保存し、`--apply` で取り込む。**通る道が違うだけで、
取り込みの検査（根拠の一節が原文にあるか、エンティティ名が登録済みか、確認状態を
出典種別から決めること）は同じ。**

```bash
cqs -w <作品> restate <版ID> --prompt            # 塊ごとのプロンプトを全部出す
cqs -w <作品> restate <版ID> --prompt --part 3   # 3番目の塊だけ出す
cqs -w <作品> restate <版ID> --apply out.json    # 返ってきたJSONを登録する
```

`--apply` に渡すのは、プロンプトが指示している形のJSON配列。塊ごとの配列を
まとめて入れ子で渡しても受ける。`-` を渡すと標準入力から読む。

```json
[
  {"text": "白草四音は葛城リーリヤの努力を「理解に苦しみますね。その努力は、無駄だというのに。」と否定した（第17話）。",
   "locator": "その努力は、無駄だというのに。",
   "entities": ["白草四音", "葛城リーリヤ"]}
]
```

捨てた件数は取り込みのときに出る。理由まで見るなら `cqs --json -w <作品> restate …` と、`--json` を作品指定の前に置く。いちばん多いのは
「根拠の一節が原文に無い」、つまり言い直しの過程で原文に無い文言が混ざった場合。

### 守っていること

- **確認状態はLLMに決めさせない**。出典種別からの機械的規則のまま（設計上の決めごと）。
  言い直すのは書き方であって、確からしさの判断ではない。
- **作り話を入れない**。各主張には根拠になった一節を原文からそのまま写させ、
  原文に無ければその主張を捨てる。空白と改行の違いは無視して探す。
- **位置を保つ**。根拠の一節が原文のどこにあるかを控えるので、並び順（時系列の
  組み立て）はこれまでどおり効く。
- 対象は登録済みのエンティティ名だけ。知らない名前は付けない。

### どの出典に掛けるか

物語を書き起こした資料（コミュの振り返り、シナリオの要約、セリフ集）に効く。
仕様の説明・一覧表・公式プロフィールは、機械的な文分割で十分なので掛けなくてよい。

費用の目安。『学園アイドルマスター』で、言い直しの対象になる資料（人物ページと
親愛度コミュの振り返り記事）は原文で約84万字あり、3,000字ずつに分けると約280回の
呼び出し、入力でおよそ100万トークンになる。全部に掛ける必要はないので、
効く出典から順に掛けるとよい。
